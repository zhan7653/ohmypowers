/goal Implement <issue-ref>. Read the issue body or local issue brief first and treat that body as the sole task contract.

If the body is incomplete or contradicts discovered facts, pause and ask to update the issue body before implementing.

Work in checkpoints:
1. Inspect the current implementation and relevant docs.
2. Make the smallest safe implementation changes.
3. Add or update tests.
4. Run validation commands.
5. Update documentation if needed.
6. Create a draft PR or MR linked to <issue-ref>.

Validation:
- Run: <command>
If these commands do not exist, discover the closest existing validation commands in the repo and document what was run.

Acceptance criteria:
Verify each acceptance criterion from <issue-ref> and record evidence for each one in the PR/MR body.

Progress:
Keep a short progress log in the PR/MR body or a local note.

Pause and ask if:
- required credentials or secrets are missing;
- the task requires changing auth or permission boundaries;
- implementation requires expanding scope beyond the issue;
- tests fail for reasons not clearly related to this task;
- existing code contradicts the issue contract;
- database migrations or destructive data changes are needed.

PR requirement:
When complete, create a draft PR or MR linked to <issue-ref>. The PR/MR body must include summary, rationale, tests run, evidence, risks, assumptions, out-of-scope items, and reviewer checklist.
Map the implementation evidence back to the issue acceptance criteria and stop condition.

For substantial follow-up work after this issue is complete, propose a new linked follow-up issue rather than extending this completed issue.

Do not merge the PR or MR.
Do not push directly to main, master, release, or protected branches.
